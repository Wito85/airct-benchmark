Finding of 9 October 2026, after the syntax check (no change of the code). The one run of syntax-check --send (9 October 2026, 04:21:17Z to 04:21:37Z; source SHA-256 as stated above; record in Section 8.10 of the amendment) ended with the message REVIEW NEEDED (exit code 4) for five of the 33 requests: R/S, DV/ai_tiab_den, DV/nonai_tiab_den, RS/S_ai and RS/S_nonai. They are the five requests that contain medline[sb], and the reason is the same for all five. PubMed returned the term in the query translation as "medlinestatus medline"[All Fields]. The rule translation_pattern_notes in airct_benchmark/run.py counts a MEDLINE filter term only in the notations medline"[filter], medline[filter], medline"[sb], medline[sb], medline"[subset] and medline[subset] (compared in lower case). This list was written during development from an assumed notation, not from the raw responses of the registered check of 4 September 2026, which were not at hand in the development environment. The test double of the suite (realistic_translation in tests/conftest.py) returns the assumed notation "medline"[Filter], so that no test could show the difference, and it was not found by the automated readings or in the review. The effect of the fault was a mark for review on every request with medline[sb]. The other parts of the rule raised no note for any of the 33 requests, no request failed, PubMed reported no error-list or warning-list entry, and the eight identities were met. The raw responses of the registered check of 4 September 2026 (prereg_syntax_check_20260904T072624Z.jsonl, SHA-256 fc286b7722bae240c06bcd0a3273f9b9c1c08fcc90d987cff7546131a373c48e, the copy kept by the guarantor) were compared on 9 October 2026: four of the 51 requests of that check contain medline[sb], PubMed returned the term as "medlinestatus medline"[All Fields] in each of them, and the translation of R/S is identical character by character to the translation of the same query string on 4 September 2026 (request CHK09_FAMILY_R_STRATUM_S_DM, count 941 on both days). The notation of PubMed is therefore unchanged since the registration, and the list in the rule was wrong from the beginning. The code is not changed: the reviewed state had been uploaded as commit f3e64d2 before the run, the rule is used by syntax-check only, and smoke, freeze and lists store every query translation as returned and do not compare it. What a person checked for the five requests is described in Section 8.10 of the amendment. For the analysis code: integrity check 5 of SAP v1.0, Section 1.4 (query translation pattern, Supplementary Table S12) has to take the notation of medline[sb] from the deposited raw responses and not from this rule.

Automated second reading of 7 October 2026. Before the first handover, the pipeline and the GBD tooling were each read by a separate automated reviewer (instances of Claude that had not written the code and were asked to find faults). Their findings were resolved before the handover. The changes that matter for the protocol:

Syntax check. The first draft of the plan contained trial numerators within Diabetes Mellitus 2015 (families DB, DC and JV and the RCT metrics of the other families). Sections 1.4 and 8.2 of the amendment state that no within-field RCT count is viewed before the freeze run. These requests were removed; the loader now refuses a plan that names one, and the command checks every request against the rule (publication year 2015 only, no Stroke heading in any spelling) before anything is sent. No such request was ever sent.
Catalogue check. The first draft searched the amendment for each template as a substring. A truncated template, two exchanged templates or an additional family would have passed. The check now compares Section 4 row by row and the panel table row by row.
Registered part of the catalogue. Its SHA-256 was read from the file itself. It is now a constant of the code; the file is read with a loader that refuses a repeated key, and every registered section is compared with the registered text after loading.
Lists. Q14 is implemented literally: a record counts as unretrievable only after six attempts. A PMID list whose length differs from its count is read again and never sampled; a failure of the service stops the run instead of drawing replacements.
GBD panel. A panel with status final can only be built from a mapping table written by reconcile, together with the ranking and the export record; check-catalogue verifies the panel file against these files. The synthetic panel of the test suite is marked and refused by every online mode. A named field cannot enter the panel under another spelling.
Hashes of deposited text files are computed on the content with LF line endings, so that Windows and Linux give the same value. A run names the SHA-256 of the package sources (source_sha256) next to the git commit, so that it stays identifiable where no git checkout exists.
